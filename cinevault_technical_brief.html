Cinevault: System Overview & Architecture

A concise, direct technical reference for presentation delivery. Explains platform purpose, user workflow, technical stack, and data flow without unnecessary embellishment.

1. The Problem & Core Solution

Streaming Paralysis vs. Vibe-Based Curation
Standard streaming platforms index 50,000+ titles but cause choice fatigue because users browse based on past watch history rather than their current mood, time constraint, and social context. Cinevault solves this by replacing infinite catalog scrolling with a 6-step progressive filter ("The Vibe Flow") that produces an immediate, high-signal shortlist ("Tonight's Feed").

2. End-to-End User Flow (4 Key Stages)

Stage User Action System Response
1. Vibe Profiler User answers 6 quick preference questions (Format, Mood, Genre, Time, Audience, Era). Validates minimum/maximum rules in memory; aggregates selections into an active filter object.
2. Tonight Feed User reviews the resulting shortlist in Grid (2:3 portrait cards) or List (editorial synopsis) view. Issues concurrent dual-page API query (40 titles); renders cached results; supports infinite scroll.
3. Deep Inspection User taps any title to view details, ratings, cast, and embedded YouTube trailer. Triggers just-in-time API enrichment for cast, director, and US streaming availability; caches in memory.
4. Collection Sync User taps Bookmark (Watchlist) or Eye (Watched) quick-action buttons. Immediately updates local sets and writes serialized IDs to browser localStorage.

3. The 6 Vibe Funnel Dimensions

Dimensions 1 – 3: Medium & Mood
  • 1. Format: Single-choice: Feature Film (movie), TV Show (tv), Limited Series (mini), Anime (anime), or Documentary (doc).
  • 2. Mood: Multi-choice (up to 3): Brain-off (comfort), Edge of Seat (suspense), Mind-bending (cerebral), Dark & Gritty, Tearjerker, Big Screen Blast.
  • 3. Genre: 18 standard cinema pills (Action, Comedy, Drama, Sci-Fi, Horror, Romance, etc.).
Dimensions 4 – 6: Constraints & Context
  • 4. Runtime: Quick (≤90m), Standard (90–125m), Epic (≥145m), or Any.
  • 5. Audience: Kids (G/PG), Family (PG-13), Date Night, Solo Adults (R/NC-17).
  • 6. Era & Language: Releases (2024–2026, 2010s, 2000s, 90s, Classics) + Language (English, Korean, Japanese, International).

Architecture, APIs & Data Lifecycle

5. Architecture & State Management

Single Source of Truth: AppContext
State is centralized at the root inside AppContext.tsx wrapping the entire application. It maintains two distinct storage tiers:
Tier A: Persistent (localStorage)

Survives page reloads and browser sessions:

  • cinevault_wl: Array of IDs saved to Watchlist.
  • cinevault_wd: Array of IDs marked Watched.
  • cinevault_tmdb_key: User custom TMDb API key.
Tier B: Transient (React useState)

Active session memory (resets on full reload):

  • feedItems: Active media list loaded in feed.
  • sel: Active vibe filter selections.
  • cur: Step index in the 6-step vibe flow.
  • mediaRegistry: In-memory Map<id, CinevaultMedia> cache.

6. State Lifecycle: What Happens When Clicking Around?

Addressing the "Feed Disappearing" Question
Internal App Navigation (Seamless): When a user clicks a movie from the feed to view /title/:id and returns via the back button, the feed does not disappear because AppContext stays mounted at the root.

Hard Browser Refresh (State Reset): If the user hits browser reload (F5) or opens the link in a new tab, React in-memory state re-initializes. Because sel and feedItems are not yet serialized to localStorage, sel resets to empty and the feed defaults back to the built-in catalog (CURATED_MEDIA_CATALOG).

Roadmap Solution: Phase 1 of the engineering roadmap syncs sel and feedItems to localStorage / IndexedDB to preserve state across hard reloads.

7. TMDb API Integration & Query Compilation Engine

The function buildDiscoverUrl() in src/services/tmdb.ts maps subjective vibe options into TMDb v3 Discover parameters:

Filter Type Vibe Input TMDb v3 Discover Parameter
Endpoint fmt: 'tv' vs fmt: 'movie' https://api.themoviedb.org/3/discover/tv vs /discover/movie
Quality Filter Global Baseline include_adult=false and vote_count.gte=20 (removes low-sample noise)
Runtime Quick (≤90m) / Epic (≥145m) with_runtime.lte=90 / with_runtime.gte=145 (Movies only)
Maturity Kids (G/PG) vs Solo (R) certification_country=US & certification=G|PG vs R|NC-17
Animation Anchor Animation requested with_genres=16,A|B (Forces animation ID 16 so live-action doesn't swamp results)

8. Critical Bug Fix: TV vs. Movie Genre Taxonomy

Why TV Returned 0 Results While Movies Returned 180+
Root Cause: TMDb uses completely different genre IDs for TV shows than for movies. For movies, Action is 28 and Adventure is 12. For TV shows, IDs 28 and 12 do not exist; TMDb combines them into 10759 ("Action & Adventure"). Similarly, Sci-Fi/Fantasy is 10765 (not 878/14). When querying TV with Movie IDs, TMDb evaluated the query as invalid and returned 0.

Resolution: Implemented TV_GENRE_TO_TMDB_ID and TV_MOOD_QUERY_PARAMS. When isTv is true, the engine dynamically swaps IDs to TV standards (e.g. Action & Adventure → 10759). The exact query now returns 1,421 TV shows.

Resiliency, Performance & Presenter Cheat Sheet

9. Performance Optimizations Implemented

Concurrent Dual-Page Fetch (40 Titles)
TMDb returns 20 titles per page. Cinevault dispatches page=1 and page=2 in parallel on initial load, doubling catalog density to 40 titles without doubling latency. Client-side Set deduplication ensures zero repeated items.
Just-In-Time (JIT) Enrichment Pipeline
Feed cards only fetch lightweight thumbnail metadata (~15KB per 20 items). Heavy details (YouTube trailers, full cast credits, and streaming provider links) are fetched on-demand only when a user opens a title, then cached in mediaRegistry.

10. Dual-Mode Resiliency: Offline Fallback Engine

Graceful Degradation Without Internet or API Keys
If no API key is provided, or if TMDb suffers rate-limiting or network downtime, fetchDiscoverMovies() catches the error and executes getCuratedMedia() across CURATED_MEDIA_CATALOG. This applies format, mood, genre, and maturity filters client-side in memory, guaranteeing the app never presents an empty or broken screen during a demo.

11. Presenter Cheat Sheet: Quick Answers for Tomorrow

Expected Question Direct Talking Point Answer
"Why did TV show return 0 results earlier?" TMDb uses distinct genre taxonomies between movies and TV (e.g. Action in Movies is ID 28, but in TV it is ID 10759). We resolved this by implementing medium-specific genre mapping (TV_GENRE_TO_TMDB_ID), which immediately expanded the match pool to over 1,400 titles.
"Where is user data saved?" Watchlists and watched history are persisted in browser localStorage. Active feed recommendations and filter selections are held in React Context memory for instant speed during the session.
"How are trailers and streaming links handled?" Trailers are embedded directly via privacy-enhanced YouTube iframe modals. Streaming availability links are dynamically compiled deep searches targeting Netflix, Prime, Disney+, Max, Apple TV, Hulu, and Criterion.
"What happens if the TMDb API goes down?" Cinevault features an automated fallback engine (getCuratedMedia) that intercepts network failures and filters a local verified catalog in memory with zero interruption to the user experience.
"What is the next technical step on the roadmap?" Phase 1: Persistent storage sync for vibe selections and feed cache in localStorage. Phase 2: Natural-language semantic vector search powered by the Gemini API to allow conversational vibe prompts.
